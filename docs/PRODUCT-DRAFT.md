## 0. 一句话与电梯稿

### 一句话

**职块是 Web3 求职 Agent：把线上岗位和线下活动收成一条可执行路径，并用周计划盯着你投递与跟进。**

### 30 秒电梯稿

职块不是又一个招聘板。你在自己的 OKX Agent 里登录钱包、交简历、开通服务，得到专属作战室。它从 web3.career / DeJob / X / Luma 等源扫机会，生成 **Plan（路径 + 本周任务）**；你在网页里改画像、记申请状态；Agent 在侧边 **催办、复盘、改稿**。投不投你拍板，**跟不跟它盯着**。

### 与「简单求职工具」的分界

| 简单工具 | 职块 |
|----------|------|
| 岗位列表 | 岗位 + 活动 + 人脉，嵌进同一条 Plan |
| 一次报告结束 | **周任务 + 跟进 + 复盘**，Agent 陪跑 |
| 你自己记得投了谁 | **申请流水线**，超时提醒 |
| 通用简历建议 | （附加）一岗一策作战包 |
| 邮箱站账号 | Agentic Wallet + 专属门户 `/p/{slug}` |

## 1. 产品目标与成功标准

### 1.1 目标用户

- 正在找或准备找 **Web3** 机会的人（全职 / 实习 / 远程 / 城市混合）  
- 角色不限：BD、Community、Research、Security、Product、Engineering 等  
- 能接受：**Agent 侧登录与付费**，网页做执行台  

### 1.2 成功标准（North Star）

优先 **投得动、跟得上**，而不是「匹配分最高」。

| 指标层级 | 指标 | 定义（建议） |
|----------|------|----------------|
| 北极星 | **周有效动作数** | 本周「已投递 + 已触达联系人 + 已报名/参加活动」合计 |
| 过程 | 开通→首次生成 Plan | ≤ 15 分钟（含交简历） |
| 过程 | Plan 生成后 7 日内 | ≥ 3 次状态更新（tracker） |
| 过程 | 跟进率 | 标记「待跟进」的项中，到期后 48h 内处理占比 |
| 体验 | Agent 陪跑触达 | 开通用户中，7 日内 ≥ 1 次 Agent 进度对话 |
| 质量（次要） | shortlist 有用率 | 用户标记「感兴趣/已投」占 shortlist 比例 |

### 1.3 非目标（本阶段不做或弱化）

- 自动代投简历到第三方网站  
- 保证拿到 Offer  
- 全网爬取所有招聘源  
- 重型 ATS 企业端  
- 把 C（作战包）做成唯一卖点（C 是附加增强）

## 2. 价值主张与卖点结构

### 2.1 主卖点 A — Web3 机会一条路径

- **线上**：多源扫岗（web3.career、DeJob、X hiring 等）→ Hybrid 匹配 shortlist  
- **线下**：Luma 等活动按城市/画像推荐，**写进同一条 Plan**，不是另开一个「活动 App」  
- **人脉**：该联系谁（LinkedIn / X 深链 + 私信草稿）挂在路径上  

**用户感知**：不用自己东搜西搜，「机会形态」统一进作战室。

### 2.2 主卖点 B — 有人盯着的周计划

- Plan 拆成 **本周可勾选任务**（投 N 岗、联 M 人、去 K 场）  
- **申请追踪** + 下次跟进日  
- **Agent 陪跑**：周一对齐、周中催办、周末复盘 → 生成下一周任务  

**用户感知**：不是看完报告就忘，有人问你「投了吗、跟了吗」。

### 2.3 附加卖点 C — 一岗一策作战包

对 shortlist 某一岗一键展开：

- 为什么推你 / 风险与缺口  
- 定制 opening（中英）  
- 建议改的 3 条 bullet  
- 联系人 + 私信（复用 A 的能力）  

**包装**：进阶能力 / 付费加项 / 「深挖这一岗」，不抢 A+B 的一句话定位。

## 3. 双端架构：网页深度 × Agent 陪跑

```
┌─────────────────────────────────────────────────────────┐
│  OKX.AI · 用户自己的 Agent（陪跑 + 开户）                  │
│  · Agentic Wallet 登录                                   │
│  · 收 PDF / 初识 / 开通付费 → 只返回 /p/{slug}            │
│  · 周计划对齐 · 催办 · 复盘 · 改 opening · 解读 JD        │
│  · （可选）触发 C：某一岗作战包                            │
└───────────────────────────┬─────────────────────────────┘
                            │ 专属链接 · 状态可读（API）
                            ▼
┌─────────────────────────────────────────────────────────┐
│  职块网页 · 作战室（深度执行）                              │
│  Setup · Plan · 本周任务 · Tracker · 活动 · 联系人        │
│  Profile · （附加）一岗一策                                │
└─────────────────────────────────────────────────────────┘
```

### 3.1 分工原则

| 事项 | 优先在 Agent | 优先在网页 |
|------|----------------|------------|
| 登录 / 付费 / 交 PDF | ✅ | 仅展示结果 |
| 改画像字段、勾任务、改状态 | 可口述同步 | ✅ 主操作 |
| 看 shortlist / 活动卡片 | 摘要 | ✅ 主浏览 |
| 催办、复盘、情绪与卡点 | ✅ | 展示结果 |
| 长文编辑简历 bullet | 可协助 | ✅ 表单/编辑器 |
| 生成 Plan / 重跑流水线 | 可触发 | ✅ 按钮 |

### 3.2 状态同源

同一用户（钱包地址）下共享：

- 画像 Profile  
- Plan / 本周任务 WeekPlan  
- 申请 Tracker  
- 活动与联系人触达状态  

Agent 与网页 **读同一份数据**（API），避免「网页改了 Agent 不知道」。

## 4. 端到端用户旅程

### 4.1 阶段 0 — 发现与开通（Agent）

1. 用户在 OKX.AI 粘贴职块 Prompt / 购买 ASP 服务  
2. Agentic Wallet 登录（链接用户自点）  
3. 提交简历 PDF → **结构化摘要**（姓名、地区、教育、经历、技能）  
4. 用户确认摘要「基本正确」  
5. 支付（生产）或 dev 开通 → **仅返回** `portalUrl`  
6. 用户自点进入专属页（默认登录）  

**原则**：网页无邮箱注册、无网页钱包登录；链接不代开。

### 4.2 阶段 1 — 作战室初始化（网页，约 10 分钟）

1. **Setup** 确认预填：称呼、角色、目标 Title、城市、薪资底线、活动城市…  
2. 点 **生成 Plan**（扫岗 + 匹配 + 活动 + 路径 + **本周任务**）  
3. 进入 **Plan** 页：看路径步骤（纵向列表）+ shortlist + 建议提升（可执行步骤）+ 活动 + 联系人  

### 4.3 阶段 2 — 执行周（网页 + Agent）— 核心体验

**网页每日/随时：**

- 勾选本周任务  
- Tracker：感兴趣 → 已投 → 面试 → …；填下次跟进日  
- 活动：报名状态；会前看准备要点（可简版）  
- 联系人：已私信 / 已回复  

**Agent 节奏（默认可写进 Prompt）：**

| 节奏 | Agent 做什么 |
|------|----------------|
| 开通当日 | 确认 portal 已打开、Setup 是否完成、是否已生成 Plan |
| 每周一 | 拉取/询问状态 → 给出 **本周 5 件事**（与网页任务对齐） |
| 周中（如周三） | 「待跟进是否过期？已投几条？」→ 催办 1–3 条具体动作 |
| 每周日 | 复盘：投了几、回了几、卡点 → 建议下调权重或改 Title → 触发「生成下周任务」 |
| 随时 | 用户丢 JD 链接/文本 → 解读是否值得投；改 opening（轻量，完整作战包见 C） |

### 4.4 阶段 3 — 深化（附加 C）

- 用户在 shortlist 点「生成作战包」或对 Agent 说「深挖 #3」  
- 输出：匹配理由、风险、opening、改 bullet、联系策略  
- 一键把「已投 + 跟进日」写入 Tracker  

### 4.5 阶段 4 — 循环

- 状态与反馈（不感兴趣、已挂）影响下一轮 shortlist / 任务  
- 画像微调后 **重新生成 Plan**，任务板重置或滚动继承未完成项

## 6. 功能模块详述

### 6.1 模块 A1 — 多源扫岗与 Hybrid 匹配（已有，保持）

- 源：web3.career、DeJob、X、（可扩展 TG 粘贴）  
- Hybrid：规则/向量召回 +（可选）LLM 精排  
- 输出：shortlist（分数、动作 apply/maybe/skip、优劣点）  

**为「投得动」服务的增强：**

- 默认 shortlist 展示 **可投递链接优先**  
- 过滤：已标记「不感兴趣」的公司/岗短期内不再推  

### 6.2 模块 A2 — 线下活动进路径（已有，加深）

- 按活动城市 + 角色/关键词匹配 Luma 等  
- 写入 Plan 步骤与 Events 页  
- **加深（执行向）**：  
  - 状态：想去 / 已报名 / 已参加 / 跳过  
  - 会前 3 条：为什么去、目标认识谁、30 秒介绍（可模板生成）  
  - 会后：一键「加联系人到触达」+ 跟进日 = 活动次日  

### 6.3 模块 B1 — 本周任务板（新建，P0）

从 Plan 自动拆出 **本周任务 WeekPlan**，例如：

| 任务类型 | 示例 | 完成定义 |
|----------|------|----------|
| apply | 投递 3 个优先岗 | Tracker 状态 ≥ 已投 |
| outreach | 联系 2 个关键人 | 触达状态 ≥ 已私信 |
| event | 处理 1 场活动 | 已报名或已跳过并写原因 |
| improve | 完成 1 条建议提升步骤 | 用户勾选完成 |
| followup | 清理过期跟进 | 无逾期项 |

规则建议：

- 每周一（或用户点「开启新一周」）生成  
- 未完成任务可 **结转** 最多 1 周，避免无限堆积  
- Agent 周中催办只盯 **未完成 + 逾期跟进**  

### 6.4 模块 B2 — 申请追踪 Tracker（新建，P0）

每条记录字段（最小集）：

- 岗位 title / 公司 / 链接 / 来源  
- 状态：`interested` → `applied` → `interviewing` → `offer` / `rejected` / `ghosted` / `withdrawn`  
- 日期：创建、状态变更、**下次跟进日**  
- 备注、关联联系人、是否来自 shortlist  

视图：

- 列表（按跟进日排序）+ 简单看板（按状态列）  
- 顶部：**逾期跟进** 红点数量（服务「跟得上」）  

### 6.5 模块 B3 — Agent 陪跑协议（新建，P0 流程 + Prompt）

**不是**再做一个网页 ChatGPT，而是：

1. 标准 **用户 Prompt**（开通 + 陪跑）  
2. 标准 **周节奏话术**  
3. Agent 可调用的只读/写入 API（或先用人机：用户粘贴状态，二期 API）  

**MVP 可先人机半自动**：

- Agent 问进度 → 用户答 → Agent 给 3 条动作 → 用户在网页勾选  
- 二期：Agent 带 address 调 `GET /api/agent/week-status` 等  

陪跑话术原则：

- 每次只给 **1–3 个具体动作**（含公司名/链接级）  
- 不替用户打开链接、不编造投递结果  
- 语言跟随用户（中/EN）  

### 6.6 模块 B4 — 建议提升可执行化（已有增强方向）

- 每条：标题 + 为什么 + **具体怎么做**（步骤列表）  
- 可勾选「本周做这一条」→ 进入任务板  
- 服务执行，而非空泛「加强技能」  

### 6.7 模块 C — 一岗一策作战包（附加，P1）

入口：

- shortlist 卡片「作战包」  
- Agent：「帮我深挖 Ave.ai 那个 BD 岗」  

输出结构：

1. 匹配理由（对照简历证据）  
2. 风险与缺口  
3. Opening / 邮件 / 约 150 字「关于我」（中英可切换）  
4. 建议改的 3 条 bullet  
5. 联系谁 + 私信草稿 + 深链  
6. CTA：标记已投、设跟进日（+3 天默认）  

商业化：可计入更高服务档或单次计量（与 A2MCP 叙事一致）。

### 6.8 模块 — 画像与简历结构化（已有）

- PDF → 姓名、地区、教育、经历列表、技能；预填 Setup  
- 原文折叠保留匹配用  
- 全角色默认策略 + 按角色微调权重/文案  

### 6.9 模块 — 触达（人脉）轻 CRM（P1）

- 从 Plan 联系人 / 活动会后沉淀  
- 状态：未联系 / 已私信 / 已回复 / 有内推  
- 跟进话术：D+3 / D+7 模板（Agent 可生成）  

### 6.10 模块 — Offer / 薪资清单（P2）

- 对照 Setup 最低月薪、token 接受度  
- 清单题：锁仓、cliff、remote、title  
- 不宣称精准估值

## 7. Plan 页信息架构（用户眼中的「成品」）

顺序建议（上→下）：

1. **状态条**：流水线进度 / 上次生成时间 / 重新生成  
2. **本周任务**（B 核心，可勾选，进度 3/7）  
3. **你应该怎么做**（路径步骤：纵向列表，每项多行 items）  
4. **优先投递** shortlist（点开可「加入追踪」/「作战包」）  
5. **建议提升**（可执行步骤 +「加入本周任务」）  
6. **适合你的活动**  
7. **该联系谁**  
8. **投递入口**（可与 shortlist 合并，避免重复感——实现时可收敛）  

顶部 Summary：多行要点，不连成一段长句。

## 8. Agent 侧成品：Prompt 与服务形态

### 8.1 两套 Prompt（建议）

| Prompt | 用途 |
|--------|------|
| **开通包** | 登录 → PDF → 付费 → 只给 portalUrl；展示结构化摘要 |
| **陪跑包** | 周计划、催办、复盘、轻量改稿、解读 JD；指引用户打开网页改状态 |

也可做成同一 Prompt 的 Phase 切换（开通完成后进入陪跑模式）。

### 8.2 ASP / 上架叙事（对齐 A+B）

- **服务名**：职块 Job Block · Web3 求职路径与周计划  
- **描述要点**：多源扫岗 + 活动进路径；专属作战室；周任务与跟进；Agent 可陪跑  
- **C**：描述里一句「支持单岗深挖作战包」即可，不占主标题  

### 8.3 计费想象（产品层，非最终商务）

| 档位 | 包含 |
|------|------|
| 基础开通 | 专属页 + Plan 生成 + Tracker + 任务板 + 活动路径 |
| 陪跑周期（如 4 周） | 基础 + 陪跑 Prompt 节奏 +（可选）优先支持 |
| 单次 C | 某一岗完整作战包 |

## 9. 关键路径与边界

### 9.1 必须遵守

- 专属链接 **用户自点**；Agent 不代开浏览器  
- 网页 **portal-only** 登录  
- 不自动对外投递  
- 不编造岗位、活动、支付结果  
- 简历与状态数据按钱包用户隔离  

### 9.2 体验红线

- 每次 Agent 回复避免堆 20 条待办 → **最多 3 条具体动作**  
- 匹配不准时：允许「不感兴趣」并减少同类，而不是硬辩  
- 扫描件 PDF 失败时：明确换文字版，不装成功

| 5 | **任务 / Tracker 基础 API** | 网页读写；`GET` 周状态供 Agent 为加分，不阻塞 1–4 |

**明确不在 Phase 1：**

- 一岗一策作战包 C  
- 活动会前/会后包、触达 CRM 状态机  
- Offer/Token 清单、模拟面试  
- Agent 自动代投、代开链接  
- 完整偏好学习重排  

**验收（锁死）：**

1. 开通用户生成 Plan 后，可见 **本周任务** 且可勾选完成  
2. 能从 shortlist **一键加入追踪**，改状态、设跟进日，见 **逾期**  
3. 陪跑 Prompt 按文档能走通：对齐 → 催办 → 复盘（半自动即可）  
4. 中英切换下上述流程可用  

### Phase 2 — A 加深 + C 附加（Phase 1 完成后再开）

1. 活动会前要点 + 会后进触达  
2. 触达状态机  
3. **一岗一策作战包 C**  
4. Agent 只读周状态 API（真陪跑自动化）  

### Phase 3 — 决策与智能迭代

1. Offer/Token 清单  
2. 偏好反馈驱动重排  
3. 模拟面试 / 公司一页纸（可选）  
4. 多周历史与简单报表（「你坚持了几周」）

### 18.2 模块说明（验收级）

#### P2-1 触达节奏
- 联系人状态：`未联系 → 已私信 → 已回复`（可扩展有内推）  
- 下次跟进日；逾期提示（复用 Tracker 逾期感）  
- D+3 / D+7 跟进话术模板（中英）  
- 可从 Plan「该联系谁」一键加入触达列表  
- **不做：** 代发私信、自动加好友  

#### P2-2 贡献式任务
- 本周任务新类型：`contribute` / 存在感（例：回 X 帖、进 TG/Discord、会前准备）  
- 生成规则：挂靠 shortlist 目标公司或推荐活动  
- 完成定义：用户勾选（与 apply/outreach 并列）  
- **不做：** 全自动社媒运营  

#### P2-4 Proof 资产卡 + 社交账号
- 从简历/画像抽出 3–5 条可展示证据（可编辑）  
- Setup / Profile 可填：  
  - `x_url` 或 handle  
  - `linkedin_url`  
  - `github_url`  
- 展示在画像与作战包/DM 引用处；一键复制「证明 + 社交链接」短文案  
- **不做：** 强制 OAuth、链上信誉评分  

#### P2-6 一岗一策 C（附加卖点）
- 入口：shortlist「作战包」或 Agent「深挖该岗」  
- 输出：为什么推你 / 风险缺口 / opening（中英可） / 建议改 3 条 bullet / 联系人+私信  
- CTA：加入追踪、设跟进日、引用 Proof  
- **不做：** 自动代投  

#### P2-7 Agent 读周状态
- 加固 `GET /api/agent/progress`：本周任务、逾期申请、**逾期触达**、open_tasks、has_path  
- 陪跑 Prompt 更新：优先催逾期投递+触达；引用 progress 字段  
- 网页与 Agent **同源**
